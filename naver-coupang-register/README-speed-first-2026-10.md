# 네이버·쿠팡 속도 우선 상품 등록

이 문서는 통합 등록 스킬의 현재 기본 실행 경로를 빠르게 확인하기 위한 별도 안내서다. 상세 절차와 화면별 참고사항은 같은 폴더의 `SKILL.md`와 `references/`를 따른다.

## 기본 경로

1. 이전 대화, Argo 기록, Aside 세션과 상품 폴더에서 이미 제공된 자료를 먼저 찾는다. 상품 첨부 흐름과 원본 이미지를 임의로 줄이거나 다른 상품 자료로 대체하지 않는다.
2. 상품별 준비 스크립트를 한 번 실행해 `registration_plan.json`을 만든다. 이는 사실과 파일 경로를 정리하는 컨테이너다. 빈 선택 필드나 선택 분석을 제출 차단 사유로 삼지 않는다.
3. 상품명, 선택 카테고리, 판매가, 실제 대표 이미지, 상세페이지, 관련 태그를 확인한다. 판매가의 출처를 기록하고, 경쟁 상품의 가격을 원가로 간주하지 않는다.
4. 판매자 화면에서 실제 필수로 표시되는 추가값과 법정 필수값만 출처를 확인해 입력한다. 필수 원산지·제조자·인증 정보가 확인되지 않으면 그 상품의 해당 마켓 제출을 보류하고 정확한 미확정 항목을 남긴다.

## 네이버 SmartStore

- Maker Selling Helper의 실제 화면에서 추출한 `maker_ui.json`을 제목·카테고리 후보·태그 근거로 사용한다. 출처는 `maker_ui`로 보존한다.
- 상품명은 `끄롱마제`로 시작하고 Maker 표현 및 확인된 상품 사실만 사용한다. 자체 브랜드 `끄롱마제`의 KIPRIS 조회는 생략한다.
- 관련 태그는 Maker 후보와 확인된 상품 표현으로 10개를 목표로 실시간 입력창에서 선택 여부를 검증한다. 근거 없는 태그를 만들지 않는다.
- F12 `terms` 수집은 사용자가 명시적으로 요청한 경우에만 한다. Maker 근거를 F12 결과로 표기하지 않는다.

## Coupang Wing

- 실시간 카테고리 검색의 상위 1~3개 추천에서 상품 용도와 맞고 선택 가능한 말단 경로를 고른다. 적합한 후보가 없을 때만 검색어를 한 번 좁혀 재검색하고, 이후에는 동일 상품에 한정된 공식 확인 경로를 사용한다. 전체 taxonomy를 수집·비교하지 않는다.
- 검색어는 Wing 추천과 확인된 상품 사실에서 관련된 표현만 입력한다. 20개는 최대치이며 미달은 경고일 뿐 등록 차단 사유가 아니다.
- 배송·반품·재고·고시·속성은 판매자 설정과 상품 근거 및 실제 필수 표시를 확인한다. 근거 없는 값이나 다른 상품의 설정을 복사하지 않는다.

## 승인과 실제 등록

요청된 여러 상품은 준비를 연속으로 진행한 뒤 하나의 간결한 통합 확인표로 보여준다. 표에는 상품별 상품명, 카테고리, 판매가와 출처, 이미지·상세페이지, 태그, 기존 상품 중복 여부, 실제 필수 판매자 값을 포함한다. 미확정 필수값과 차단 사유를 숨기지 않는다.

사용자가 그 확인표를 명시적으로 승인하기 전에는 네이버 `저장하기`나 Wing의 최종 `상품등록`을 누르지 않는다. 승인된 값이 바뀌면 변경분을 다시 보여주고 재승인을 받는다. 승인 후 상품을 순차 제출하고, 각 마켓에서 등록 ID·심사 및 판매 상태·재고를 확인한다. 공개 상품 페이지에서 품절 여부와 구매 동작을 검증한 다음, 네이버와 쿠팡 결과를 각각 Argo에 기록한다.

## 실행 도구

```text
python "<skill>\scripts\prepare_product.py" "<완료폴더 경로>" --out "<작업 폴더>"
python "<skill>\scripts\build_confirm_table.py" --plan "<상품 1 plan>" --plan "<상품 2 plan>" --out "<작업 폴더>\confirm.md"
```

제출 버튼을 누르기 전 `confirm.md`의 전체 내용을 사용자에게 보여준다. 실제 판매자 화면 입력·중복 확인·등록 결과 검증은 계정 스킬의 `references/naver-smartstore.md`와 `references/coupang-wing.md`를 따른다.
