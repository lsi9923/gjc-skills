## 속도 우선 등록 기준

- 기본 경로는 네이버 Maker Selling Helper의 실제 `maker_ui.json`이다. Maker UI에서 키워드 칩·카테고리 후보·태그 후보를 먼저 읽고, 상품명은 원상품 사실과 결합해 끄롱마제로 빌드한다(추출기에 title 필드 없음). F12 `terms`/`intersectionTerms` 수집은 사용자가 명시적으로 요청한 경우에만 한다.
- Maker UI 값은 `maker_ui` 출처로 유지한다. Maker JSON에 없는 검색량·숨은 탭·부가 패널을 추가 수집하거나 전체 스키마 완성도를 심사하지 않는다.
- 상품명은 원상품 사실에 맞고 끄롱마제 브랜드명으로 시작하며 중복·경쟁 브랜드·허위 기능이 없어야 한다. 길이는 검색 최적화 참고값이지 제출 blocker가 아니다.
- 네이버 태그는 고유하고 상품과 맞는 10개를 목표로 스마트스토어 라이브 태그 입력창에서 선택 여부를 검증한다. Maker 도우미의 '연관 키워드/태그' 탭에 추출된 태그 칩(`.nvs-tag-chip`)을 1순위로 채택하며, 태그 칩이 비어 있거나 부족하면 노출된 키워드 칩(`searchVolumes.word`)과 원상품 사실적 표현으로 채워 넣는다(지어내기 금지, 미달은 WARN). F12 근거가 없다는 이유로 태그 확정을 멈추지 않는다.
- Coupang 카테고리는 Wing 검색창 결과 상위 1~3개에서 경로와 말단 ID를 확인하고 실제 상품과 일치하는 선택 가능 후보를 고른다. 맞는 후보가 없으면 query를 한 번 좁혀 재검색한 뒤, 동일상품 seller listing ID → 이전에 기록된 공식 ID → 정확히 일치하는 원상품 공개 Coupang 경로 순으로 대체 후보를 찾는다. 후보는 공식 tree 1회 조회/공식 lookup 1회와 live 선택으로 검증한다. 전체 taxonomy/API 또는 약 5.5만 행 자료는 수집·비교하지 않는다. 검증된 후보가 없으면 Coupang만 blocker로 두고 네이버 등 다른 마켓은 계속한다. 후보가 충돌하면 확인표에 함께 보여주고 사용자가 선택한다.
- Coupang 검색어는 화면 추천어와 실제 상품 사실에서 관련 있는 항목을 가능한 만큼 입력한다. 20개 미달·검색 포화·별도 term provenance JSON은 blocker가 아니다. 관측되지 않은 기능·재질·규격이나 무관어를 만들어 채우지 않는다.
- 완성 필수값은 상품명, 카테고리, 가격, 이미지, 상세페이지, 관련 태그다. 이외에는 실제 제출 화면의 필수 표식 또는 법적 필수 요건만 blocker다. 선택값·검색량·완전한 JSON·전체 SEO 감사는 완료 게이트가 아니다.
- 명시적 사용자 승인 전 최종 저장/등록 버튼을 누르지 않는다. 여러 상품은 준비를 연속 처리하고 간결한 통합 확인표 한 번으로 승인받은 뒤 순차 제출한다.


## 사용자 자체 브랜드 규칙 (필수 준수)

- **자체 브랜드명**: **`끄롱마제`** (판매자 소유 고유 브랜드)
- **상품명 맨 앞 배치**: 상품명 작성 시 맨 앞(0번)에 반드시 자체 브랜드 **`끄롱마제`**를 먼저 배치하고, 그 뒤에 완성형 0번 텀스 및 조합형 텀스를 이어붙인다.
  - 형식: `끄롱마제 [완성형 텀스] [조합형 텀스...]`
  - 권장 길이: 공백 포함 25~35자 (INFO; 공식 상한 100자). 중복·근거 없는 표현은 사용하지 않는다.
- **판매자 속성 입력**:
  - 브랜드 칸: **`끄롱마제`**
  - 제조사 칸: **`협력업체`** (원산지: 중국 사실대로 반영)
  - 모델명: **`단일상품`** 또는 설정안함
- **KIPRIS 예외**: 자체 브랜드 `끄롱마제`는 등록 중 KIPRIS 조회를 생략한다. 예외는 이 이름에만 적용하고 제3자·경쟁 브랜드에는 적용하지 않는다.
- **태그 목표**: 네이버 스마트스토어는 Maker 후보를 기반으로 관련 태그 10개를 목표로 한다. 쿠팡 검색어는 가능한 관련어를 입력하되 20개 미달은 제출을 막지 않는다.

## 네이버 (Maker 기본, 이호 F12는 사용자 요청 시)

랭킹 = 적합도(컷오프) + 인기도 − 신뢰도 감점. 적합도 가중: 카테고리 > 상품명 > 스토어명 > 브랜드/제조사 ≫ 속성·태그.

### 선택 F12/이호 분석 절차 — 명시 요청 시만

아래 1–8번은 사용자가 F12 terms 분석을 요청했을 때만 따른다. Maker 기본 경로에서는 실행하거나 필수 결과로 요구하지 않는다.

1. 대표 키워드 정하기: 원상품 제목·섹션 카피에서 상품을 가장 정확히 부르는 말(예: `모양펀치`, `퍼즐펀치`).
2. 카테고리(강의 2-1): `scripts/naver_search_extract.js`·`scripts/naver_f12_capture.js` 로 대표 키워드들을 검색해 저장한 JSON 을 `scripts/naver_category_pick.py --in-dir <f12폴더>` 로 합친다. 출력 `leafCandidates` 의 relevance 가 1.0에 가까운(nearOne) 후보를 따라가되, 실제 상품과 성별·용도·품목이 같은 말단만 선택. `parentChildConnected:false`(부모 연결 없음) 후보를 임의 조합하지 않는다(스크립트가 서로 다른 키워드 카테고리를 섞지 않음). `--product-use` 로 용도 불일치 경고를 받고, `verdict:"판정불가"`면 스마트스토어 카테고리 검색창에서 실제 선택 가능한 말단인지 사용자와 확인.
3. 키워드 수집(2-2): 추출 결과 `relatedQueries`, 상위 비광고 상품 제목, `topTagFrequency` 에서 원상품과 실제 관련 있는 단어만. 타브랜드·무관어 제외.
4. 완성형/조합형/연결형/교집합/미적용(2-3B/2-5): `scripts/naver_f12_capture.js` 로 F12 패킷의 `terms`·`intersectionTerms` 를 읽고, `scripts/naver_title_builder.py` 가 이호 규칙으로 자동 판정한다(근거는 lecture_rules §3).
   - **완성형**(§3-2): 검색어가 terms 에 통째로 한 덩어리(유산균→[유산균]). 상품명 앞자리, 붙여쓰기.
   - **조합형**(§3-3): terms 에서 여러 단어로 쪼개짐(질유산균→[질,유산균]). 왼→오 순서·거리 최소 배치.
   - **연결형**(§3-6): 붙여도 한 덩어리지만 "띄어서" 재검색해도 여전히 한 덩어리(생유산균). 완성형처럼 취급, 사이에 단어 넣지 말 것. 판별을 위해 `생 유산균`처럼 띄운 변형도 함께 검색.
   - **교집합**(§5-2): terms 엔 없지만 intersectionTerms 로 이동. 적합도는 정상 반영.
   - **미적용**(§3-4): 수식어가 terms 에서 사라짐(유산균추천→[유산균], '추천' 소멸). 상품명·태그에서 제거.
   - **동의어**(§3-5): terms 로는 못 가림. 두 키워드 총상품수가 거의 같으면 동의어(둘 중 하나만).
5. 상품명(2-4, lecture_rules §4): 가장 중요한 완성형을 맨 앞(0번, 좌측 가점). 조합형은 왼→오·거리 최소(공통 꼬리 term 을 공유하는 조합형은 접두어를 모으고 공통 꼬리 1회로 묶어 거리 최소화 — §4-2/§4-3). 동일 단어는 조합 성립에 꼭 필요한 1회만. 공백 포함 25~30자 권장(최대 35자, WARN) — 단 근거 없는 단어로 채우지 않는다(공식 상한은 100자, BLOCK). 특수문자·홍보·배송·혜택·옵션포괄 문구 금지(§8.1 검색품질 곱셈감점). `naver_title_builder.py` 가 상품명 후보 2개(대형/틈새 전략)를 글자수·단어별 근거와 함께 낸다. 우선순위 판단에 월검색수가 필요하고 네이버 검색광고 API 자격증명(환경변수)이 있으면 `scripts/naver_searchad_volume.py --keywords ... --out vol.json` 결과를 `naver_title_builder.py --search-volume vol.json` 로 넘긴다(선택). 자격증명 미설정이면 `available:false`+exit 0 이므로 검색량 없이 진행한다(자격증명은 환경변수 전용, 파일 저장 금지).
6. 검증(2-5, §5): 완성 상품명 전체로 다시 검색해 `naver_f12_capture.js` 를 `{title: 상품명}` 으로 실행 → 단어별 terms/intersection/누락 표시. 누락 단어는 교체, 카테고리 relevance 유지 확인. `seo_audit.py --plan` 이 `IHO_HEAD_COMPLETE`(완성형 0번)·`IHO_COMBO_ORDER`(조합형 왼→오)를 자동 게이트로 검사.
7. 태그(2-3 편법 제외, §6): 상품명에 못 넣은 유효 키워드 → 태그 10개. 스마트스토어 태그 입력창에서 사전 등록(선택 가능)되는 태그만 확정. 띄어쓰기 없이. 제한/홍보/타브랜드 태그 제외([사용 금지]).
8. 속성(§7): 카테고리 속성 중 원상품 근거가 있는 값만 선택. 모르면 비워 둔다. 무관/타브랜드 목적의 속성 입력은 [사용 금지](신고 대상).

### 메이커 셀링 도우미(크롬 확장) — 기본 경로
실제 확장 UI에서 `maker_ui.json`을 추출해 보이는 상품 키워드·추천 카테고리·스마트스토어 태그를 사용한다. 이 자료는 F12가 아닌 독립 근거로 저장한다. 검색량 `-`는 미수집으로 취급하고 등록 blocker로 만들지 않는다. 태그 칩이 사전 선택 가능인지 폼에서 확인하며, 확인되지 않은 경우에도 F12를 추가 수집하지 말고 해당 후보만 대체한다.

이호의 F12 terms 분류는 사용자가 직접 요청한 선택 경로다. 이호 강의의 25~35자 권장 길이, 완성형·조합형 판정 및 검색량 비교는 SEO 개선 참고사항이며 기본 등록의 필수 게이트가 아니다.

## 쿠팡

- 노출상품명: `끄롱마제`로 시작하고 확인된 제품명을 쓴다(최대 100자, 옵션값 제외). `scripts/coupang_helper.py`는 제3자 제거 대상 브랜드와 옵션값만 빼고 자체 브랜드를 유지한다. 근거 없는 단어로 길이를 늘리지 않는다.
- 검색어: Coupang 검색창 또는 Wing 추천에 보이는 표현과 원상품 사실을 사용한다. 최대 20개는 플랫폼 한도이며 최소 등록 수가 아니다. 적은 검색어 수는 참고 WARN으로만 남기고 제출하지 못하게 하지 않는다.
- 태그는 상품의 실제 용도·기능과 맞는지 간단히 대조한다. 타브랜드·홍보어·중복·무관어·상품에 없는 재질·기능·규격은 제외한다. 별도 query·캡처 provenance JSON은 기본 작업에서 요구하지 않는다.
- 카테고리: Wing 실시간 검색 추천 상위 1~3개에서 말단 경로와 ID를 확인해 가장 맞는 선택 가능 후보를 고른다. 전체 분류표 대조나 상위 판매자 조사로 확장하지 않는다. 적합한 말단이 없을 때만 한 차례 검색어를 좁혀 재검색한다.
- 검색필터(속성)·구매옵션: 카테고리가 요구하는 필수 구매옵션(수량, 색상, 용량 등)은 실제 값으로. 색상은 쿠팡 표준명(화이트/블랙/그레이). `coupang_category_pick.py --attributes-json`(화면 필터 스펙)으로 색상=표준명 정규화·숫자형=숫자만·enum 범위 밖/근거 없음 비움·품절 옵션(`droppedOptions`) 제외를 판정한다.
- 고시정보: 카테고리가 지정한 품목군 항목명 그대로. 원상품 근거값 우선, 없는 항목만 `상세페이지 참조`.

## 금지 (RED)

타브랜드 삽입, 가구매·지인구매·보상리뷰, 클릭/트래픽 봇, 최신성 목적 판매상태 토글, 인증·원산지·브랜드·속성 추측, 근거 없는 수식어(추천/인기/신형/고급 등)로 글자수 채우기, 캡차·차단 우회.
