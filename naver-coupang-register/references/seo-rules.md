## 네이버 (이호 방식)

랭킹 = 적합도(컷오프) + 인기도 − 신뢰도 감점. 적합도 가중: 카테고리 > 상품명 > 스토어명 > 브랜드/제조사 ≫ 속성·태그.

1. 대표 키워드 정하기: 원상품 제목·섹션 카피에서 상품을 가장 정확히 부르는 말(예: `모양펀치`, `퍼즐펀치`).
2. 카테고리(강의 2-1): `scripts/naver_search_extract.js`·`scripts/naver_f12_capture.js` 로 대표 키워드들을 검색해 저장한 JSON 을 `scripts/naver_category_pick.py --in-dir <f12폴더>` 로 합친다. 출력 `leafCandidates` 의 relevance 가 1.0에 가까운(nearOne) 후보를 따라가되, 실제 상품과 성별·용도·품목이 같은 말단만 선택. `parentChildConnected:false`(부모 연결 없음) 후보를 임의 조합하지 않는다(스크립트가 서로 다른 키워드 카테고리를 섞지 않음). `--product-use` 로 용도 불일치 경고를 받고, `verdict:"판정불가"`면 스마트스토어 카테고리 검색창에서 실제 선택 가능한 말단인지 사용자와 확인.
3. 키워드 수집(2-2): 추출 결과 `relatedQueries`, 상위 비광고 상품 제목, `topTagFrequency` 에서 원상품과 실제 관련 있는 단어만. 타브랜드·무관어 제외.
4. 완성형/조합형/연결형/교집합/미적용(2-3B/2-5): `scripts/naver_f12_capture.js` 로 F12 패킷의 `terms`·`intersectionTerms` 를 읽고, `scripts/naver_title_builder.py` 가 이호 규칙으로 자동 판정한다(근거는 lecture_rules §3).
   - **완성형**(§3-2): 검색어가 terms 에 통째로 한 덩어리(유산균→[유산균]). 상품명 앞자리, 붙여쓰기.
   - **조합형**(§3-3): terms 에서 여러 단어로 쪼개짐(질유산균→[질,유산균]). 왼→오 순서·거리 최소 배치.
   - **연결형**(§3-6): 붙여도 한 덩어리지만 "띄어서" 재검색해도 여전히 한 덩어리(생유산균). 완성형처럼 취급, 사이에 단어 넣지 말 것. 판별을 위해 `생 유산균`처럼 띄운 변형도 함께 검색.
   - **교집합**(§5-2): terms 엔 없지만 intersectionTerms 로 이동. 적합도는 정상 반영.
   - **미적용**(§3-4): 수식어가 terms 에서 사라짐(유산균추천→[유산균], '추천' 소멸). 상품명·태그에서 제거.
   - **동의어**(§3-5): terms 로는 못 가림. 두 키워드 총상품수가 거의 같으면 동의어(둘 중 하나만).
5. 상품명(2-4, lecture_rules §4): 가장 중요한 완성형을 맨 앞(0번, 좌측 가점). 조합형은 왼→오·거리 최소(공통 꼬리 term 을 공유하는 조합형은 접두어를 모으고 공통 꼬리 1회로 묶어 거리 최소화 — §4-2/§4-3). 동일 단어는 조합 성립에 꼭 필요한 1회만. 공백 포함 25~30자 권장(최대 35자, WARN) — 단 근거 없는 단어로 채우지 않는다(공식 상한은 100자, BLOCK). 특수문자·홍보·배송·혜택·옵션포괄 문구 금지(§8.1 검색품질 곱셈감점). `naver_title_builder.py` 가 상품명 후보 2개(대형/틈새 전략)를 글자수·단어별 근거와 함께 낸다. 우선순위 판단에 월검색수가 필요하고 네이버 검색광고 API 자격증명(환경변수)이 있으면 `scripts/naver_searchad_volume.py --keywords ... --out vol.json` 결과를 `naver_title_builder.py --search-volume vol.json` 로 넘긴다(선택). 자격증명 미설정이면 `available:false`+exit 0 이므로 검색량 없이 진행한다(자격증명은 환경변수 전용, 파일 저장 금지).
6. 검증(2-5, §5): 완성 상품명 전체로 다시 검색해 `naver_f12_capture.js` 를 `{title: 상품명}` 으로 실행 → 단어별 terms/intersection/누락 표시. 누락 단어는 교체, 카테고리 relevance 유지 확인. `seo_audit.py --plan` 이 `IHO_HEAD_COMPLETE`(완성형 0번)·`IHO_COMBO_ORDER`(조합형 왼→오)를 자동 게이트로 검사.
7. 태그(2-3 편법 제외, §6): 상품명에 못 넣은 유효 키워드 → 태그 10개. 스마트스토어 태그 입력창에서 사전 등록(선택 가능)되는 태그만 확정. 띄어쓰기 없이. 제한/홍보/타브랜드 태그 제외([사용 금지]).
8. 속성(§7): 카테고리 속성 중 원상품 근거가 있는 값만 선택. 모르면 비워 둔다. 무관/타브랜드 목적의 속성 입력은 [사용 금지](신고 대상).

### 메이커 셀링 도우미(크롬 확장) — 보조 참고자료
`scripts/maker_helper_extract.js` 로 확장이 렌더한 텀 칩(완성형/조합형)·카테고리·검색량·스마트스토어 태그를 읽을 수 있다. **F12 근거를 보조하는 참고자료로만** 쓰고, 상품명·태그 확정은 어디까지나 F12(terms/intersection/relevance) 근거로 한다. 확장이 없으면(`available:false`) 건너뛴다. 확장 파일은 수정하지 않고, 이 스크립트가 외부 서버(searchad/maker39)를 직접 호출하지 않는다(확장이 이미 렌더한 값만 읽음).

## 쿠팡

- 노출상품명: 공식 권장 `[브랜드]+[제품명]`, 최대 100자. 브랜드 제거 규칙 때문에 브랜드 칸은 `브랜드 없음/자체제작` 처리하고 상품명은 제품명 중심. `scripts/coupang_helper.py` 가 옵션값(색상·수량)·브랜드를 제거한 `exposureName` 을 만든다(색상은 쿠팡 표준명 정규화). 핵심 소구점 + 메인 키워드 + 용도/대상, 5~8단어. 60~90자로 억지로 늘리지 않는다 — 근거 있는 단어만. (하드코딩 F자패턴·태그풀은 이식하지 않음)
- 검색어: 최대 20개, 개당 20자, 허용 특수문자 `!@#$%^&*-+;:'.`. `coupang_helper.py --keyword-json <title_build.json>` 이 네이버 F12 판정 통과 키워드(완성형/조합형/연결형/교집합)와 태그 후보에서만 검색어 슬롯을 채운다. **20개를 근거로 못 채우면 미만으로 둔다(지어내기 금지).** 추가 소스: Wing 등록화면 추천 검색어, Wing 인기검색어 도구(`coupang-trends/popularity-search`), 쿠팡 검색창 자동완성 중 상품과 맞는 것 — 화면에서 읽은 단어만 `--sources-json`(`wingRecommended>wingPopular>coupangAutocomplete>naverF12` 우선순위)으로 넘겨 소스별로 귀속한다(같은 단어는 높은 소스 1회, `searchTermsBySource`·`inName`·`exposureIssues` 로 요약). 상품과 무관한 키워드·타브랜드로 채우지 않는다.
- 카테고리: Wing 카테고리 검색/추천에서 말단 선택. 쿠팡에서 같은 상품 상위 판매자의 카테고리 경로와 대조. 화면에서 읽은 후보만 `coupang_category_pick.py --candidates-json` 으로 점수화(reasons 근거)하고, 후보가 없으면 경로를 지어내지 않는다.
- 검색필터(속성)·구매옵션: 카테고리가 요구하는 필수 구매옵션(수량, 색상, 용량 등)은 실제 값으로. 색상은 쿠팡 표준명(화이트/블랙/그레이). `coupang_category_pick.py --attributes-json`(화면 필터 스펙)으로 색상=표준명 정규화·숫자형=숫자만·enum 범위 밖/근거 없음 비움·품절 옵션(`droppedOptions`) 제외를 판정한다.
- 고시정보: 카테고리가 지정한 품목군 항목명 그대로. 원상품 근거값 우선, 없는 항목만 `상세페이지 참조`.
