- 꼬봉: OmO(브라우저 입력 단독), gjc(근거 찾기·부가 작업·스킬 기록, Muse 대신).

## 시작 전 점검 (매 세션, 재부팅 후 필수)
1. Aside 메인 창 존재: `Get-Process Aside | ? MainWindowTitle`. 없으면 `Start-Process 'C:\Program Files\Aside\Application\Aside.exe'`.
2. 로그인 탭은 사용자에게 보이는 창에 연다: `Start-Process '...Aside.exe' -ArgumentList 'https://sell.smartstore.naver.com/','https://wing.coupang.com/'`. `aside repl openTab()`은 안 보이는 창이라 로그인용으로 쓰지 않는다.
3. 네이버는 '커머스 ID(이메일)' 로그인. '네이버 아이디로 새로 가입' 창이 뜨면 취소.
4. 로그인 확인은 사용자 답 또는 페이지 제목으로 검증한 뒤 OmO 시작.

## 작업 순서 (상품마다)
1. gjc: 근거 수집(원본 폴더 metadata/source/result, 1688·쿠팡 치수·소재, Maker 실브라우저 추출 `maker_ui.json`). 합성·임의 ID 금지.
2. Claude: 상품명·태그·검색어·고시·카테고리 확정(한 번에 표로).
3. OmO: 네이버 → 윙 순서로 입력, 임시/중간저장, 재오픈 확인. 막히면 1회 재시도 후 `[OmO 오류]`.
4. gjc: 다음 상품 근거를 OmO 입력과 동시에 준비.

## 속도 설계 (2026-10-18 Claude·agy 합의, 구현 전)
1. 상품별 `spec.json` 1개(확정값) → 마켓별 재사용 스크립트 `fill_naver.js`·`fill_wing.js`가 입력+임시/중간저장+저장 JSON 검증을 aside repl 한 번 호출로 끝낸다. 필드마다 repl 왕복 금지.
2. gjc 사전 수집에 윙 말단 카테고리 ID와 그 카테고리의 필수 옵션축 스키마(모델명/품번, 3축 여부)를 포함한다. 윙 입력은 DOM 클릭 대신 Vuex preFill 활용 가능.
3. 감사: 윙은 appData.drafts·draft GET JSON, 네이버는 판매자센터 세션 안의 임시저장 상세 XHR JSON(page.evaluate fetch). 외부 Commerce API는 임시저장 조회가 안 될 가능성이 높다.
4. 사용자 결정은 gjc가 전 상품의 윙 카테고리·필수 옵션축·브랜드 상태를 1차 스캔한 직후 한 번에 🟡로 묻는다.
5. gjc가 다음 상품 근거를 OmO 입력과 병렬로 준비.

## 판단 기본값 (묻지 말고 적용)
- 윙 카테고리: 검색 Top1~3 → 1회 다른 검색어 → 단계별 트리. 하위 섹션(옵션·고시)이 열려야 리프. 사용자 선호 경로(예: 의자커버)가 트리에 있으면 그쪽.
- 윙 필수 옵션축 '모델명/품번': 자체 코드·타사 번호 금지, Maker 칩+검색어 기반 서술형(예: '충전식 무선 미니 빗고데기').
- 근거 없는 고시값(사용자 지시 2026-10-17): 수치·날짜·인증번호 같은 사실값은 지어내지 않는다. 취급 주의사항처럼 문장형 필수칸은 빈칸으로 두지 말고, 확인된 사실(소재·자석·크기 등)에서 나오는 보수적 주의 문구를 바로 작성해 넣는다(묻지 않음).
- 브랜드 '추가하기'는 사용자 승인 후에만.
- 인증: 사용자 지정(구매대행/대상 아님)을 따른다. 타사 KC 번호 금지.
- 윙 브랜드 심사 완료 전에는 '브랜드 없음' 체크 유지. 해제하면 노출상품명이 0/100으로 초기화·비활성되고 저장 목록 상품명도 공란이 되어 재오픈 식별이 막힌다. 승인 후 해제→끄롱마제 선택→노출상품명 재입력.
- 윙 고시: 값 입력 전에 상품군 드롭다운(주방용품·패션잡화 등)부터 바꾼다. 기본값(의류/선택하세요)에 입력 금지.
- 네이버 태그: Maker 상위 칩 중 제품 사실과 안 맞는 것(판고데기·의자양말 등)과 네이버가 거부하는 일반명사(고데기)는 빼고, 같은 .nvs-tag-chip 목록의 다음 순위 사실 일치 칩으로 채워 10개.
