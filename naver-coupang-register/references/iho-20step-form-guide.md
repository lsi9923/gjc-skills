# 네이버쇼핑 상품등록 (적합도·인기도·신뢰도 실전 프로토콜)

출처: 최이호 「온라인 진실의 방」 강의 정리본. 사용자가 네이버쇼핑 상품등록, 상품명 작성, 카테고리 선정, 키워드 소싱, 상위노출 진단을 요청하면 이 문서의 순서대로 진행한다.

## 0. 알고리즘 전제 (판단의 기준선)

```
최종 랭킹 = [적합도 (진입 장벽)] + [인기도 (순위 결정력)] − [신뢰도 감점]
```

- **GBDT는 전환율 공식이 아니다.** 2022년 도입된 GBDT의 본질은 검색어–상품 적합도가 기준치 미만이면 클릭·판매량이 아무리 높아도 상위 노출에서 잘라내는 **컷오프 필터**다. "GBDT = 클릭 대비 전환율"은 오해다.
- **적합도가 0이면 인기도 100만 점도 1페이지 진입 불가.** 따라서 작업 순서는 항상 적합도 → 신뢰도 → 인기도.
- 적합도 가중 서열: **카테고리(절대적) > 상품명(핵심) > 스토어명 > 브랜드/제조사 ≫ 속성·태그(미미), 이미지 0%**
  - 이미지는 적합도 점수와 **무관**. 워터마크·텍스트 과다·해상도 미달을 거르는 품질 필터일 뿐 가산점이 없다. 사용자가 "이미지 최적화로 적합도 올린다"고 하면 바로잡을 것.

## 1단계. 카테고리 확정 — relevance 실측 (가장 중요)

외부 솔루션(아이템스카우트 등)의 카테고리 비율은 **현재 등록된 상품 수의 백분율 통계**일 뿐, 네이버가 부여하는 실제 가점이 아니다. 반드시 실측한다.

> 실증: '트레이닝복' — 솔루션은 남성의류 67% > 여성의류 32%. 그러나 실제 relevance는 **여성의류 0.53 > 남성의류 0.46**.

**확인 절차**

1. 크롬에서 네이버쇼핑 접속 → 타깃 키워드 검색
2. `F12` → **Network** 탭
3. 검색 결과의 **'가격비교' 탭** 클릭
4. 패킷 목록에서 `all?eq=...` 요청 클릭
5. 우측 **Preview → shoppingResult → cmpOrg** 확장
6. `category1` ~ `category4` 트리에서 각 카테고리의 **`relevance`** 확인

**해석**

- `relevance` 1.0 = 적합도 만점. 예) category1에서 `식품`이 1.0이면 식품 외 카테고리 등록 시 가점 0.
- `category2`와 `category3`은 **인덱스 순서로 짝 매칭**된다 (category2의 0번 ↔ category3의 0번). 대분류부터 세분류까지 **조합 전체**의 relevance가 가장 높은 경로를 고른다.
- 0.04 수준의 카테고리는 사실상 노출 불가 — 솔루션 통계로는 이 판별이 안 된다.
- relevance는 **고정값이 아니다.** 구매자 검색·클릭·구매 패턴 학습으로 주기적 갱신되므로 소싱·등록 전마다 재확인한다.

## 2단계. 상품명 설계 — 적합도 만점 5대 규칙

1. **완성형 키워드는 왼쪽에.** 네이버 사전에 한 단어로 등록된 키워드는 앞쪽에 있을수록 가점 최대.
2. **조합형 키워드는 간격을 좁게.** 구성 단어 사이 거리가 멀수록 감점. (예: `질`과 `유산균` 사이에 다른 단어가 끼면 감점)
3. **조합형은 좌 → 우 순서 유지.** 검색엔진이 인식하는 형태소 순서와 일치해야 조합 가점을 받는다. 순서 역전 시 가점 누락.
4. **길이는 공백 포함 25~30자 (최대 35자).** 과거 50자 기준은 폐기됨. 상품명 간소화 로직상 길면 감점 요소.
5. **중복 키워드는 예외적으로 1회만.** 남발 금지. 조합 구조 완성을 위해 불가피할 때만 1회 추가 배치.

**작성 프로세스**

1. 키워드를 완성형 / 조합형 / 제외로 분류
2. 내 상품 경쟁력에 따라 대형 키워드 vs 중소형 조합 중 주력 결정
3. 완성형 앞단 배치 → 조합형 간격 축소·좌우 순서 정렬 → 불필요한 띄어쓰기 제거로 25~30자 맞춤
4. 아래 terms 검증

## 3단계. terms / intersectionTerms 검증

작성한 상품명을 실제로 네이버쇼핑에 검색해 F12 네트워크 패킷의 `terms`, `intersectionTerms`에 잡히는 단어가 상품명에 빠짐없이 들어있는지 확인한다. 여기에 매칭돼야 적합도 만점이 나온다.

- **사전 미등록어 분해**: `햇완두콩` 검색 → terms는 `햇완두` + `완두콩`으로 분리. 단일 명사로 없어도 두 조각이 상품명에 조합돼 있으면 노출된다.
- **유사 확장 매칭**: `연초필터` 검색 → terms에 `담배`·`필터`·`연초`가 함께 잡힘. 네이버가 유사 카테고리 대표 키워드를 끼워 넣으므로, 그 구조를 역이용해 상품명을 구성해야 누락이 없다.
- `intersectionTerms`(복합 검색어의 필수 공통 형태소)에 포함된 단어가 상품명에 없으면 필터링에서 밀린다.

## 4단계. 스토어명 · 브랜드 · 속성/태그

- **스토어명**: 공식 가이드에 없지만 실제로 강한 가산 요소. 스토어명에 타깃 키워드가 있으면 적합도 우위(예: '닭갈비' 검색 ↔ 스토어명 '진실의방 닭갈비'). 단, 단일 품목 전문몰이 되어 카테고리 확장이 막히는 단점이 있으므로 주력 단일 카테고리 운영일 때만 권한다.
- **브랜드/제조사**: 필드 자체 기여는 미미. **상품명 안에 녹일 때** 유효 키워드로 더 강하게 작동한다.
- **속성·태그**: 가산점 극히 미미. 여기에 시간 쓰지 말 것. 상품명에 못 넣은 서브·잉여 키워드를 담는 그릇으로만 쓴다. **태그 사전에 등록된 태그만 인식**되고, 등록돼 있어도 검색에 안 걸리는 유령 태그가 다수 존재하므로 실제 매칭 여부를 검증한다.

## 5단계. 신뢰도 100점 방어 (감점제)

신뢰도는 쌓는 점수가 아니라 **100점에서 깎이는 구조**이며, 관여 항목은 단 2개다.

1. **상품명 검색품질 체크** — 단어 반복, 특수문자 등 위반 시 가중치(`totalscore`)가 0.7·0.3 등으로 곱해져 대폭 감점. 등록 시 반드시 통과시킨다.
2. **네이버쇼핑 패널티** — 배송지연, 품절 취소, 가이드 위반. 적발 시 신뢰도 0점 → 상품·스토어 전반 랭크다운, 회복 어려움.

규정만 지키면 누구나 100점이므로 차별화 요소가 아니라 **생존 조건**이다.

## 6단계. 인기도 설계 — 최신성이 지배한다

네이버 인기도는 누적이 아니라 **최근성** 중심이다.

| 항목 | 집계 기준 | 실무 포인트 |
|---|---|---|
| 클릭수 | **직전 7일** (8~9일 전 순차 소멸) | 인기도 중 **가중치 최강**. 8일차에 최대 반영 |
| 판매실적 | 최근 **2일 > 7일 > 30일** 가중 | 30일 초과 누적은 사실상 가산점 제외 (화면의 6개월 누적 구매건수는 순위 미반영) |
| 리뷰수 | 카테고리 내 상대 환산 | **약 1,000개에서 만점 수렴** — 그 이상은 차이 없음. 신규 셀러의 격차 극복 지점 |
| 찜수 | 최근 7일 | 반영되나 순위 기여 미미 |
| 최신성 | 등록 시 **100점 → 20~25일마다 20점 차감** | 공식은 30일 주기지만 실제는 카테고리별 20~25일 |

**골든타임 = 등록 후 20~25일.** 최신성 100점 구간에 클릭과 판매를 집중시켜야 효과가 극대화된다. 클릭 단독으로는 1페이지에 못 간다 — 최신성 + 판매와 결합될 때 순위가 뛴다.

**최신성 재부여**: 최신성이 빠졌거나 시즌이 끝난 상품은 30일간 전시/판매 중지 후 31~32일차에 판매중으로 되돌리면 최신성이 재부여된다(삭제 후 재등록과 다름). 단 **중지 기간 동안 누적 유입·기존 랭킹 점수가 전부 소멸**하고 반복 시 어뷰징 탐지 대상이 될 수 있으므로 **순위권 상품에는 절대 쓰지 말고** 순위권 밖 상품에만 제한적으로 쓴다.

## 7단계. 키워드 선정과 '누울 자리' 분석

검색량이 아니라 **진입 가능성과 실판매**로 고른다. 월 검색수 2,000 수준이어도 틈새 수요·독점 구조면 큰 매출이 난다. 경쟁강도가 낮은 키워드는 1페이지 상품들의 클릭 점수도 낮게 형성돼 있어 적은 컨트롤로 상위 진입이 가능하다.

**1페이지 진단 3종**

1. **매출 분포 유형**
   - *상단 집중형*(1~5위만 판매, 아래는 0건): 최상단까지 밀어 올릴 여력 없으면 진입 지양.
   - *분배형*(10~30위권도 꾸준히 판매): 20~30위 목표만으로 실판매 가능 → 공략 적합.
2. **묶음 락 확인**: 상위 구간이 세트·다묶음으로만 채워져 있으면 단품 진입이 막혀 있으니 회피.
3. **상위 상품 스펙**: 1페이지에 최근 등록 상품이 거의 없으면 최신성 가산점만으로 제칠 수 있다. 리뷰 수십 개 이하, 씨앗·새싹 등급 셀러가 다수면 난이도 매우 낮음. 한 업체가 도배한 키워드도 클릭 장벽이 낮다.

## 8단계. 경쟁사 실측 (외부 솔루션 수치를 믿지 말 것)

솔루션의 '7일 판매량'은 대개 **2주 전(월~일) 데이터**이고 '건수' 기준이라 대량 구매 옵션의 실제 개수를 반영하지 못한다. 현재 순위 싸움 추적에는 쓸모가 없다.

- **네이버쇼핑 재고**: F12 → Network → Fetch/XHR → `stockQuantity` 검색 → 옵션별·총합 실시간 재고
- **쿠팡 재고**: F12 → 모바일 뷰 전환 → F5 → `남은 수량은` 검색
- 6시간 또는 1일 단위로 엑셀에 기록 → 차감분 = 실제 판매 개수
- 스토어 전체상품 **'인기도순' = 직전 3일 실제 판매 개수 순**

**해석 주의**: ERP·통합솔루션을 쓰는 대형 셀러는 타 플랫폼 판매·도매 출고·임의 재고 수정으로 재고가 급변하므로 차감분을 곧바로 판매량으로 단정하지 말 것. 또한 플랫폼 패치로 `stockQuantity` 같은 키값이 비노출·암호화될 수 있다.

## 9단계. 진입 실행 및 8일차 점검

1. 목표 순위(예: 20~30위) 주변 상품의 최근 2~7일 판매 건수를 위 방법으로 벤치마킹
2. 골든타임(등록 후 20~25일) 안에 클릭 유입과 판매를 그 벤치마크 위로 끌어올림
3. **8일차에 순위 점검** — 미진입이면 원인은 대개 **클릭 점수 부족**이므로 유입을 보강한다

**클릭이 인정되는 유입 vs 아닌 유입**

- 유튜브 더보기·댓글 링크를 타고 들어온 유입은 네이버 검색 클릭수·판매점수에 **직접 반영되지 않는다.**
- 영상 자막·음성으로 **고유 키워드(브랜드명+상품명)를 직접 검색해 들어오게** 유도해야 검색 클릭점수로 인정된다. 오타 위험이 적고 중복 상품이 없는 고유 키워드를 설계할 것.

## 하지 말아야 할 것 (신뢰도 0점 영역)

강의에는 가구매·리뷰 작업이 언급되지만, 이는 네이버 이용약관 위반이며 강의 자체의 결론과도 충돌한다. **제안하거나 실행 방법을 안내하지 않는다.**

- 적발 시 해당 상품 신뢰도 **0점 강등 → 검색 노출 배제**, 스토어 전반 랭크다운. 앞 단계에서 쌓은 적합도·인기도가 전부 무의미해진다.
- 탐지 엔진은 IP, 배송지 주소 패턴, 결제 수단, 송장 추적(빈 박스 배송) 등으로 고도화돼 있어 소규모라도 결제 흐름이 부자연스러우면 걸린다.
- 사용자가 이 방향을 물으면 리스크를 짚고, 대체 수단(정상 광고·프로모션·체험단, 검색 유도형 콘텐츠 마케팅, 실판매 기반 리뷰 확보, 옵션별 리뷰 분산)으로 돌린다.
- '네이버 내부 권한·해킹으로 정확한 클릭수를 안다'고 주장하는 트래픽 대행사는 허위일 가능성이 높다. 직접 트래킹하는 쪽이 안전하다.

## 작업 체크리스트

| 단계 | 확인 사항 |
|---|---|
| 카테고리 | relevance 실측으로 최고 조합 확정 (툴 비율 무시) |
| 상품명 | 완성형 좌측 / 조합형 인접·좌우 순서 / 25~30자 / 중복 최대 1회 |
| 검증 | terms·intersectionTerms 전부 매칭 |
| 스토어명 | 주력 단일 카테고리면 키워드 포함 검토 |
| 속성·태그 | 잔여 서브 키워드만, 사전 등록 태그 검증 |
| 신뢰도 | 상품명 검색품질 체크 통과, 배송지연·품절취소 0 |
| 인기도 | 등록 후 20~25일 골든타임에 클릭·판매 집중 |
| 점검 | 8일차 순위 확인 → 미진입 시 클릭 보강 |

## 주의

여기 담긴 수치와 메커니즘은 공식 문서가 아니라 강의자의 역추적·경험칙이다. 네이버는 알고리즘과 데이터 노출 구조를 수시로 패치하므로 F12 절차나 키값이 더 이상 동작하지 않을 수 있다. 확인이 안 되면 추정으로 단정하지 말고 사용자에게 현재 화면에서 보이는 값을 확인하도록 안내한다.

# 실행 모드 — 상품등록 폼 자동 작성

사용자가 이 스킬을 부르고 **상품 URL**(도매/제조사/경쟁사 상세페이지)을 주면, 위 알고리즘 원리를 적용해 **스마트스토어 상품등록 폼의 모든 항목을 채운 결과물**을 출력한다. 사용자는 그 결과를 보고 복붙으로 등록만 하면 되도록 한다.

## A. 진행 순서

**1) 상품 정보 추출**
URL을 열어 다음을 뽑는다. 접근이 막히면(로그인 필요, 차단 등) 아래 목록을 사용자에게 요청한다.
- 품목명·정확한 종류 / 브랜드·제조사 / 모델명
- 규격(사이즈·중량·용량) / 소재·성분 / 구성·수량 / 색상·옵션
- 원산지 / 인증(KC 등) / 유통기한·제조일 유무
- 매입가 또는 참고 판매가 / 이미지 개수

**2) 키워드 도출**
추출한 정보로 메인 키워드 1개 + 서브 키워드 후보 5~10개를 뽑고, 완성형 / 조합형 / 제외로 분류한다.

**3) 실측값 확보 (사용자 협조 필요)**
나는 브라우저 F12를 직접 열 수 없다. 다음 두 가지는 사용자가 확인해 붙여넣어야 정확도가 올라간다.
- 타깃 키워드의 **카테고리 `relevance`** (1단계 절차)
- 상품명 후보의 **`terms` / `intersectionTerms`** (3단계 절차)

실측값이 없으면 **추정 1차안**을 만들되, 출력 맨 위에 `※ 미검증 항목` 으로 카테고리와 상품명을 표시하고 검증 절차를 함께 안내한다. 검증됐다는 말을 임의로 하지 않는다.

**4) 판매자 고정정보 확인 (최초 1회)**
매번 물을 필요 없는 값이다. 처음 한 번 받아 두고 이후 재사용한다.
출고지 주소 / 반품·교환지 주소 / 택배사 / 반품배송비·교환배송비 / A/S 전화번호 / A/S 안내 문구 / 사업자 상호 / 배송비 정책(무료·조건부·유료)

**5) 폼 출력** — 아래 B의 표를 그대로 채워서 낸다.

## B. 출력 템플릿 (이 순서·이 항목 전부)

각 항목은 `값` + 필요 시 `근거 한 줄`로 낸다. 값이 확정 불가면 빈칸으로 두지 말고 `[확인필요: 사유]`로 표기한다.

### 1. 카테고리 `필수`
- 전체 경로: 대분류 > 중분류 > 소분류 > 세분류 (**최종 카테고리까지** 반드시)
- relevance 근거 또는 `[미검증]` 표기
- ⚠ 안 맞는 카테고리 등록 시 강제 이동·판매중지·판매금지 대상

### 2. 예약구매
- 기본 `설정안함`

### 3. 상품명 `필수`
- **25~30자(최대 35자)** — 입력창은 100자까지 받지만 강의 기준을 따른다
- 완성형 좌측 / 조합형 인접 + 좌→우 / 중복 최대 1회
- 글자 수를 반드시 세어서 함께 표기 (예: `28자`)
- 대안 2안까지 제시 (A안: 대형 키워드 / B안: 중소형 조합)

### 4. 판매가 `필수`
- 판매가 / 즉시할인 `설정안함` / 판매기간 `설정안함` / 부가세 `과세상품` (식품·농산물 등은 `면세상품` 검토)
- ⚠ 판매가·할인가를 활용한 비정상 거래는 자동 탐지되어 판매지수에 미포함

### 5. 재고수량 `필수`
- 옵션 사용 시 옵션 재고 합계로 자동 입력됨

### 6. 옵션
- 단독형/조합형, 옵션명·옵션값·재고
- 없으면 `설정안함`

### 7. 상품이미지/동영상 `필수`
- 대표이미지: **1000×1000** (최소 300×300)
- 추가이미지: 최대 9개 — 무엇을 찍을지 리스트로 제안
- **적합도 가산점은 0이다.** 다만 워터마크·과도한 텍스트·규격 미달은 저품질 필터에 걸리므로 규격만 지킨다
- 동영상: 최대 1분 권장
- **동영상 타이틀 (20자)** — 통합검색 노출에 활용되는 문구이므로 상품명에 못 넣은 서브 키워드를 여기 넣는다

### 8. 상세설명 `필수`
- 구성안을 섹션 단위로 제시 (후킹 → 핵심 스펙 → 사용법 → 상세 규격표 → 배송/교환 안내)
- 권장 가로 848px
- ⚠ 외부 링크를 통한 개인정보 수집 금지, http 이미지 금지(https), 네이버 외 외부링크·스크립트 자동 삭제, 상품과 무관한 내용 시 판매금지

### 9. 상품 주요정보 `필수`
- 모델명 / **브랜드** / **제조사** — 없으면 `설정안함`. 단 유효 키워드는 상품명 안에 녹인다
- **상품속성**: 카테고리 선택 후 활성화. **주요 속성만 정확히.** 무관하거나 과도한 속성 선택 시 정상 노출되지 않는다
- KC인증: `KC인증 있음/없음` + 해당 사유(구매대행 / 안전기준 준수 / KC 안전관리대상 아님)
- 인증정보: 인증기관·인증번호
- 원산지 `필수`
- 상품상태 `신상품` (중고를 신상품으로 등록 시 판매금지·미노출)
- 맞춤제작 / 제조일자 / 유효일자
- 미성년자 구매 `가능/불가능`

### 10. 사이즈
- 의류·잡화 등 해당 카테고리면 `설정함` + 사이즈 분류(상품군) + 모델정보
- 해당 없으면 `설정안함`

### 11. 상품정보제공고시 `필수`
- `설정함` + 상품군 선택 + 고시 항목 값 전부 채움 (품목별 필수 기재사항)

### 12. 배송 `필수`
- 배송여부 `배송` / 배송방법 `택배,소포,등기` / 배송속성 `일반배송` (**'오늘출발'은 지킬 수 있을 때만** — 배송지연은 신뢰도 감점 직결)
- 택배사 / 묶음배송 `가능` / 상품별 배송비(무료·조건부·유료·수량별)
- 제주·도서산간 추가배송비 / 지역별 차등 배송비 / 별도 설치비
- 출고지

### 13. 반품/교환 `필수`
- 반품/교환 택배사 / 반품배송비(편도) / 교환배송비(왕복) / 반품교환지

### 14. A/S, 특이사항 `필수`
- A/S 전화번호 / A/S 안내 문구 / 판매자 특이사항
- ⚠ 법령에 근거 없는 임의 판매규정·청약철회 기준 기재 시 제재

### 15. 추가상품
- 함께 팔면 좋은 구성 제안 (추가상품명 / 값 / 가격)
- 기본상품과 동일한 상품은 추가상품 등록 불가

### 16. 구매/리뷰 혜택 조건
- 최소구매수량 (네이버쇼핑 노출가 = 상품금액 × 최소구매수량 — 노출가가 왜곡되지 않게 주의)
- 최대구매수량 / 복수구매할인
- **포인트: 구매 시 지급 + 리뷰 작성 시 지급 — 적극 설정 권장.** 리뷰는 인기도 점수이자 1,000개 만점 수렴 구간까지 밀어야 할 지표이고, 정상적인 리뷰 확보 수단이다
- 무이자할부 / 사은품 / 사은품 이미지(500×500, 텍스트 이미지 불가)
- 이벤트 문구 — **검색 대상에 포함되지 않으므로 키워드를 넣지 말 것.** 혜택만 적는다

### 17. 검색설정
- **태그: 최대 10개.** 상품명에 못 넣은 서브·틈새 키워드만 담는다
  - 카테고리명 / 브랜드명 / 판매처명이 포함된 태그는 **등록 자체가 안 된다**
  - 상품과 무관한 태그는 판매금지 사유
  - 입력 후 **`검색에 적용되는 태그 확인`** 버튼으로 반드시 검증 (사전 미등록·유령 태그 거르기)
- Page Title / Meta description — 각각 제안값 작성

### 18. 판매자 코드
- 판매자 상품코드 / 바코드 / 내부코드1 / 내부코드2 (내부 관리용, 랭킹 무관)

### 19. 노출 채널 `필수`
- 채널명 `스마트스토어` 체크
- 스마트스토어 전용 상품명: 원칙적으로 **사용 안 함** (전용 상품명을 쓰면 네이버쇼핑에 그 이름이 우선 노출되어 최적화한 상품명이 무력화될 수 있음)
- **가격비교 사이트 등록 `네이버쇼핑` 반드시 체크** — 반영까지 2~8시간(지연 시 1~2일)
- 전시상태 `전시중` / 알림받기 동의 고객 전용상품 / 공지사항

### 20. 마지막 필수 절차
- 저장 전 **`쇼핑 상품정보 검색품질 체크`** 버튼 실행 → 통과 확인
- 이게 신뢰도 100점의 관문이다. 통과 못 하면 앞의 모든 최적화가 감점으로 상쇄된다

## C. 출력 뒤에 항상 붙일 것

1. **미검증 항목 목록** — 사용자가 F12로 확인해야 할 값과 그 절차
2. **등록 직후 액션 플랜** — 골든타임 20~25일 기준 일정, 8일차 순위 점검 시점
3. **감점 위험 체크** — 이번 등록에서 걸릴 수 있는 항목(배송속성, 태그, 이벤트 문구, 속성 과다 등)

## D. 지키지 않을 것

- 확인 안 된 스펙을 지어내지 않는다. 원산지·인증·성분·용량은 **틀리면 판매금지·법적 제재 사유**이므로 추측 금지, `[확인필요]`로 남긴다.
- 타 셀러의 상세페이지 문구·이미지를 그대로 복제하지 않는다. 스펙(사실)만 참고하고 문구는 새로 쓴다.
- 가구매·리뷰 작업은 제안하지 않는다 (위 '하지 말아야 할 것' 참조).
