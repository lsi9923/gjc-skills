# Aside ↔ Argo Vault 연동

## 기본 대상

- Argo vault: `C:\Users\imda0\.argo\vault`
- 기본 프로젝트: `끄쫀꾸`
- 프로젝트 허브: `vault\notes\끄쫀꾸.md`
- 대화 핸드오버: `vault\conversations\끄쫀꾸\YYYY-MM-DD-<slug>.md`
- 링크 인덱스: `vault\_index.md`

경로가 없거나 사용자가 다른 Argo 회사·워크스페이스를 지정하면 임의로 쓰지 말고 확인한다.

## 읽기

1. `_index.md`에서 프로젝트 허브와 관련 노트를 찾는다.
2. 현재 요청과 직접 관련된 노트만 읽는다.
3. Argo 기록은 과거의 참고자료로 취급하고, 현재 파일·사이트 상태와 사용자의 최신 지시로 확인한다.
4. 모순된 기록은 최신 근거를 우선하고, 오래된 기록은 덮어쓰지 말고 superseded 상태를 남긴다.

## 쓰기

`끄쫀꾸` 관련 작업이면 사용자가 별도로 저장을 말하지 않아도 작업 종료 시 구조화된 핸드오버를 만든다. 사용자가 다른 프로젝트를 지정하거나 저장하지 말라고 한 경우에만 기본 동작을 바꾼다.

핸드오버 형식:

- 날짜와 작업명
- 사용자 목표
- 확인된 사실과 근거
- 확정된 결정
- 변경·실행한 내용
- 검증 증거
- 미해결 문제와 차단 조건
- 다음 행동
- 관련 위키 링크

기본값은 전체 원문 대화 복사가 아니라 요약 핸드오버다. 사용자가 "전체 대화 저장"이라고 명시한 경우에만 원문에 가깝게 저장한다.

프로젝트 허브에는 장기적으로 재사용할 결정과 현재 상태만 갱신한다. 세부 로그는 `conversations\끄쫀꾸`에 새 파일로 추가한다. 반복 저장은 `scripts\sync-handover.ps1`을 사용해 중복 파일명과 인덱스 링크를 안전하게 처리한다. 기존 기록을 삭제하거나 무단으로 덮어쓰지 않는다.

## 자동 저장 기본값

- 기본 프로젝트는 `끄쫀꾸`다.
- 사용자가 저장을 따로 말하지 않아도 관련 작업 시작 시 Argo 원본과 허브를 읽고, 작업 종료 시 핸드오버 파일과 허브의 최근 핸드오버 링크를 갱신한다.
- 네이버·쿠팡 상품 등록도 상품 폴더, SEO 근거, 입력값, 검증 상태, 승인 경계, 등록 결과를 Argo에 자동 기록한다.
- 짧은 인사·단순 질의는 저장하지 않고, 결정·작업·조사·검증이 포함된 대화만 저장한다.
- 전체 원문 저장은 사용자가 명시적으로 요청한 경우에만 하며, 기본은 구조화된 요약이다.
- 자동 저장은 외부 등록·게시·결제 승인을 대신하지 않는다. 승인 전에는 초안·입력·검증만 기록한다.

## Gajae-Code 결합

- 심층 인터뷰 결과는 `명세` 섹션으로 저장한다.
- 계획·비평 결과는 `계획`과 `검토` 섹션으로 저장한다.
- 목표별 결과는 `완료`, `차단`, `검증 증거`로 저장한다.
- 연구 결과는 `근거`, `한계`, `결론`으로 저장한다.
- Argo에는 Gajae-Code 전용 `.gjc` 상태를 복사하지 않고, 사람이 읽을 수 있는 결정·근거·핸드오버만 저장한다.

## 안전 규칙

- 비밀번호, 인증번호, API 키, 토큰, 쿠키, 개인정보를 저장하지 않는다.
- 외부 게시·등록·삭제·결제의 승인 자체는 Argo에 기록하지 않고, 승인된 범위와 결과만 기록한다.
- 저장 성공은 파일 존재와 내용 재읽기로 확인한다.
- Argo UI가 꺼져 있어도 Markdown 원본을 저장할 수 있지만, UI 그래프 인덱스가 자동 갱신되는지는 별도로 확인한다.
- 관련 작업은 자동 저장 대상으로 취급하되, 짧은 인사·단순 질의는 저장하지 않는다. 저장 성공은 스크립트 출력과 파일 재읽기로 확인한다.
